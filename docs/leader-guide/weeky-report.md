# 리더 운영가이드 - 주간 개발회의

## 1. 회의 목적

주간 개발회의는 단순한 업무 보고가 아니라, **팀 전체의 프로젝트 진행 상황을 공유하고 파트 간 협업과 의사결정이 필요한 사항을 조율하는 정기 회의**다.

리더는 회의를 통해 다음 내용을 관리한다.

* 전체 프로젝트 진행 상황 공유
* 금주 주요 결정사항 공유
* 차주 주요 일정 및 결정 예정사항 공유
* Release, PoC, 고객 발표 등 주요 이벤트 공유
* 파트별 진행 업무 및 예정 업무 확인
* 파트 간 협업 요청 및 건의사항 확인
* 회의 후 Action Item 관리

---

## 2. 참석 대상

주간 개발회의는 개발 조직 전체가 참석한다.

* BE
* FE
* SE(DevOps)
* 리더

현재 SE 인원은 1명이지만, 향후 인원이 증가하더라도 동일한 파트 단위로 운영한다.

회의는 개인별로 모든 업무를 발표하는 방식보다는 **BE, FE, SE 파트별로 대표자가 주요 내용을 공유하는 방식**으로 진행한다.

---

## 3. 회의 진행 순서

### ① 리더 전체 현황 공유

회의 시작 시 리더가 전체 프로젝트 관점에서 주요 사항을 먼저 공유한다.

주요 공유 항목은 다음과 같다.

* 전체 프로젝트 진행 상황
* 금주 주요 결정사항
* 차주 결정 예정사항
* Release 일정
* PoC 일정
* 고객 발표 및 데모 일정
* 고객 대응 및 프로젝트 주요 이벤트
* 팀 전체가 사전에 인지해야 할 일정 또는 Risk
* 파트 간 협업이 필요한 주요 사항

리더는 개별 개발 업무를 대신 설명하기보다 **프로젝트 전체의 방향, 일정, 우선순위, 주요 의사결정 사항을 공유하는 역할**에 집중한다.

---

### ② 파트별 진행사항 공유

다음으로 파트별로 발언권을 부여한다.

기본 진행 순서는 다음과 같다.

**BE → FE → SE**

각 파트에서는 한 명이 대표로 다음 내용을 공유한다.

* 금주 수행 업무
* 현재 진행 중인 업무
* 차주 예정 업무
* 일정 또는 기술적 Risk
* 다른 파트와 협의가 필요한 사항
* 리더의 판단이나 결정이 필요한 사항

개인별 업무를 모두 나열하기보다 **파트 전체에서 중요도가 높은 업무와 일정, 이슈를 중심으로 공유한다.**

---

## 4. 요청 및 제안사항 공유

파트별 발표에는 업무 진행 상황뿐 아니라 다른 파트 또는 리더에게 요청하거나 제안하고 싶은 내용도 포함한다.

예:

* BE에서 FE에 요청할 사항
* FE에서 BE에 필요한 API 또는 일정 요청
* 개발 파트에서 SE에 요청할 배포·환경 관련 사항
* SE에서 개발팀에 요청할 배포 구조 또는 설정 변경사항
* 특정 개발자와 협의가 필요한 사항
* 리더의 우선순위 결정이 필요한 사항
* 개발 프로세스 또는 협업 방식 개선 제안
* 개발환경 및 도구 관련 개선 요청

이를 통해 개인 간 요청으로 끝날 수 있는 내용을 **팀 차원의 공식 협업사항으로 공유하고 정리한다.**

---

## 5. 자유 질의 및 건의

모든 파트 발표가 끝난 후 리더가 참석자들에게 추가적으로 궁금한 점이나 건의사항이 있는지 확인한다.

이 시간에는 업무 보고에 포함되지 않은 내용도 자유롭게 이야기할 수 있다.

예:

* 조직 운영 관련 의견
* 업무 배분 관련 의견
* 개발 프로세스 개선
* 일정에 대한 우려
* 기술 검토 요청
* 필요한 지원사항
* 협업 과정에서 발생하는 문제

리더는 이 과정에서 즉시 결정 가능한 사항은 결정하고, 추가 검토가 필요한 사항은 Action Item으로 남긴다.

---

## 6. Action Item 관리

회의가 종료되면 회의에서 발생한 후속 업무를 Action Item으로 정리한다.

특히 다음 내용은 반드시 Action Item으로 관리한다.

* 회의 중 새롭게 요청받은 업무
* 다른 파트에서 전달받은 요청
* 리더가 확인해야 할 사항
* 추가 기술 검토가 필요한 사항
* 일정 확인이 필요한 사항
* 차주까지 결정해야 하는 사항

가능하면 다음 세 가지를 함께 기록한다.

**Action Item / 담당자 / 목표 일정**

예:

| Action Item          | 담당 | 목표 일정     |
| -------------------- | -- | --------- |
| Gateway 성능 테스트 조건 정리 | BE | 차주 회의 전   |
| Admin API 변경사항 FE 공유 | BE | 금주        |
| 운영 배포 환경 확인          | SE | Release 전 |
| PoC 고객 일정 확인         | 리더 | 금주        |

Action Item은 단순 회의 기록이 아니라 **다음 업무 진행 상황을 추적하는 기준**으로 활용한다.

## 8. 리더의 역할

주간회의에서 리더가 모든 개발자의 업무를 직접 취합하고 대신 설명하는 구조는 지양한다.

리더의 핵심 역할은 다음 네 가지다.

**전체 현황 공유 → 파트 간 연결 → 의사결정 → 후속조치 확인**

각 파트의 업무는 해당 파트가 직접 설명하고, 리더는 전체 프로젝트 관점에서 다음 사항을 관리한다.

* 우선순위
* 일정
* 파트 간 의존성
* 주요 Risk
* 의사결정 필요사항
* 외부 일정 및 고객 대응
* 후속 Action Item

주간회의의 목적은 **“누가 어떤 일을 했는가”를 확인하는 것이 아니라, 현재 프로젝트의 상태와 다음 단계, 그리고 이를 위해 필요한 협업과 의사결정을 팀 전체가 동일하게 인지하도록 하는 것**이다.
